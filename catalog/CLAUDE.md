# CLAUDE.md — altaco-catalog

Ти будуєш сайт-каталог ALTACO (преміальний натуральний та інженерний камінь, Київ). Фаза 1 платформи. ТЗ і acceptance checklist — PHASE1_BRIEF.md. Фотоконвенція — PHOTO_GUIDE.md.

## Інваріанти даних (специфікація, не побажання)

1. `data/altaco_materials.json` — заморожений контракт. Код адаптується під дані, ніколи навпаки. Жодних правок JSON і схеми без явного дозволу людини, включно зі статусами і «очевидними помилками» — знайшов проблему в даних: СТОП, питання людині.
2. Фото: файлова система — source of truth, конвенція `photos/{id}/slab.jpg` + `detail-1.jpg`. Шляхи в JSON руками не прописуються.
3. Публічні ціни — тільки retail з контракту. `qty_slabs`, `notes_internal`, `todo_manual` не потрапляють у жоден публічний build-артефакт (HTML, JS, JSON-LD, sitemap, фіди, sourcemaps) — лише узагальнений бейдж наявності з поля `stock_location` (kyiv/dnipro/on_order). SHOW_DRAFTS у production — завжди false.
4. `hidden`-позиції не існують для фронтенду: ні сторінок, ні sitemap, ні /catalog.json.
5. Валідація проти схеми + обидві integrity-перевірки — обов'язкова частина build. Build падає на невалідних даних.
6. Жодних вигаданих матеріалів, цін, описів. Порожнє поле → секція не рендериться.

## Session Protocol

- Перший коміт: DECISIONS.md з шаблону DECISIONS.template.md (план + розділ «Backlog / Marketplace»).
- Працюй до умови завершення: всі АВТОМАТИЧНІ пункти acceptance checklist (PHASE1_BRIEF.md §5–6) зелені. Ручні пункти познач «до перевірки людиною» — їх закриває Олександр на чекпоінті.
- Неоднозначність у межах фронтенду — вирішуй сам, один рядок у DECISIONS.md: що, чому, як відкотити.
- Конфлікт із контрактом даних — СТОП, питання людині.
- Репозиторій — твоя пам'ять: README, DECISIONS.md, коміт-меседжі (українською) пишуться так, щоб наступна сесія відновила контекст без людини.
- Заблокований відсутнім ресурсом (фото, токени) → плейсхолдер + запис у DECISIONS.md + рух далі.

## Скоуп

Фаза 1 = каталог + картки + /catalog.json + /llms.txt. Без консультанта, КП-генератора, бекенду, CMS. Ідеї — у DECISIONS.md розділ «Backlog / Marketplace», не в код. Фаза 1 — перший read-only шар платформи ALTACO Marketplace (бриф §0): не блокуй майбутні склад/адмінку/КП, але й не будуй для них заготовок.

## Стиль

- Мова інтерфейсу українська, i18n-ready ключі без хардкоду рядків.
- Якісний орієнтир: шоурум преміального італійського каменю, не інтернет-магазин плитки. Камінь — герой, інтерфейс — рамка.
- Design-токени: з [DESIGN TOKENS] промпту; якщо порожньо — нейтральна преміальна база, всі рішення ізольовані в tailwind.config + tokens.css для заміни однією правкою (зафіксувати в DECISIONS.md).
- Тексти інтерфейсу стримані: без захоплених прикметників, без «це не X, це Y», мінімум довгих тире.
