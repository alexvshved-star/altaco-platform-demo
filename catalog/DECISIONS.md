# DECISIONS.md — altaco-catalog

Сесія 2026-06-10 · вхід: PHASE1_BRIEF.md + CLAUDE.md + презентація платформи (макети стор. 8–9, кропи в `docs-mockups/`).

## План сесії

1. Звірити контракт даних з ТЗ, зафіксувати розбіжності (розділ «Рішення», Р-01).
2. Скаффолд Astro 5 + Tailwind 4 + TS, статичний експорт; дані лише через `src/lib/catalog.ts`.
3. Схема контракту (`altaco_materials.schema.json` — артефакт агента під фактичні дані) + `scripts/validate-data.mjs` (schema + integrity) як обовʼязковий крок build.
4. Сторінки: каталог `/` (сітка, фільтри з фасетів, лічильник, сортування за ціною) + картка `/katalog/{id}` за макетами стор. 8–9.
5. SEO/GEO: canonical, sitemap, robots (агенти не блокуються), JSON-LD з контракту, `/catalog.json` + `catalog.public.schema.json`, `/llms.txt`, hreflang-структура.
6. Скрипти перевірок: `check-public-artifacts.mjs` (grep dist на внутрішні поля), `test-negative-data.mjs` (білд падає на зламаній копії), Playwright smoke.
7. Прогін acceptance-чеклісту §5–6, чесні відмітки, фінальний звіт.

## Рішення

- **Р-01 · Контракт ≠ ТЗ.** Фактичний заморожений контракт — демо `0.1.0-demo` (поля: `id, name, type, line, finish, price_eur_m2, photo, tags, published:bool`), а не `v1.0.0-rc2` з брифу (немає `slab_groups`, `qty_slabs`, площ, `origin`, `color`, товщин, розміру сляба, статусів draft/hidden, `notes_internal`, `todo_manual`, схеми, фото). · Чому: §7.3 / CLAUDE.md №1 — код адаптується під дані, дані недоторканні. · Відкат: замінити data/altaco_materials.json багатим контрактом — модель (`types.ts`) уже приймає його опціональними полями, UI оживе без переписування.
- **Р-02 · Статуси.** `published:true` → публікується; `published:false` → еквівалент draft (показ лише локально при SHOW_DRAFTS, з генерованим плейсхолдером) і hidden (у production не існує: 404, нема в sitemap/фідах/JSON-LD). · Чому: у контракті один boolean на три статуси ТЗ. · Відкат: enum-статус у даних → одна функція `isVisible` в catalog.ts.
- **Р-03 · Ціни = 0.** Усі `price_eur_m2: 0` — явні плейсхолдери (`$comment_price`). Рендеримо «Ціна за запитом», у JSON-LD Offer без `price` (фейковий 0 — брехня в розмітці), у /catalog.json `price_eur_m2: null`. Логіка «від €min» реалізована й оживає з реальними цінами. · Чому: CLAUDE.md №6 — жодних вигаданих цін. · Відкат: реальні ціни в JSON → все вмикається само.
- **Р-04 · Integrity-перевірки.** €/slab ≈ €/м² × площа (≤5%) реалізовано у validate-data.mjs, але на демо-даних N/A (немає per-slab цін і площ) — скрипт явно звітує SKIP з причиною, не фейкове PASS. Друга перевірка (узгодженість посилань line→lines, унікальність id, slug-чистота) — активна. · Відкат: зʼявляться групи — перевірка вмикається сама.
- **Р-05 · Фільтри.** Фасети генеруються з даних: тип, лінія, фініш, теги. Колір/товщина/наявність із макета — N/A: полів немає в контракті, порожніх фільтрів не робимо (аналог «порожніх полиць»). · Відкат: нове поле в даних → новий фасет у `getFacets()`.
- **Р-06 · Наявність (СУПЕРСЕДЖЕНО Р-24).** Спершу поля наявності не було → бейдж-заглушка й `PreOrder` у JSON-LD. Тепер наявність задає поле `stock_location` (kyiv/dnipro/on_order) — див. Р-24.
- **Р-07 · Фото.** Файлова система — source of truth за PHOTO_GUIDE.md (`photos/{id}/slab.jpg`, `detail-1.jpg`); поле `photo` в JSON ігнорується (вказує на неіснуючі файли, руками не редагується). Файлів зараз нема → детермінований генерований SVG-патерн з назвою (не сток). · Відкат: покласти фото за конвенцією — підхопляться білдом.
- **Р-08 · Стек.** Astro 5 + Tailwind 4 + TS strict, static output (рекомендація брифу §3). Типи написані вручну в `types.ts` синхронно зі схемою замість json-schema-to-typescript: схема — теж артефакт цієї сесії, генерація з неї дала б ілюзію незалежної перевірки. · Відкат: підключити json-schema-to-typescript у build.
- **Р-09 · Токени.** [DESIGN TOKENS] у промпті порожній → діють значення брифу §4 (`#F1EEE7`/`#131A24`/`#B9985A`, Playfair Display + Manrope, КАПС-лейбли). Ізольовано в `src/styles/tokens.css` — заміна однією правкою після підтвердження Ігорем.
- **Р-10 · Кнопки картки.** «Запросити КП» → mailto з темою-айдішником; «Додати в запит» → Telegram-лінк. Без бекенду (§1). Контакти в `src/config.ts` — плейсхолдери до підтвердження. «Підібрати альтернативу» з макета — Фаза 2 (консультант), не рендеримо.
- **Р-11 · Розташування.** Проєкт у `catalog/` монорепо `altaco-platform-demo`; канон даних — `../data/altaco_materials.json`, читається build-time через fs рівно в одному модулі `src/lib/catalog.ts`. · Чому: README репо визначає `catalog/` як Фазу 1 над спільним ядром.

- **Р-12 · Контраст vs канон золота.** Дрібний латунний текст на слоновій кістці (#B9985A на #F1EEE7 = 2.35:1) провалює WCAG AA. Введено `--alt-brass-text: #7d6536` (4.79:1) для дрібного тексту і `--alt-brass-deep` (3.36:1) для великих цін; на темному тлі канонічний #B9985A без змін. · Чому: Lighthouse A11y впав би нижче порога; токени ізольовані — Ігор може переграти однією правкою. · Відкат: повернути #B9985A у tokens.css.
- **Р-13 · Playwright 1.56.0 (пін).** CDN браузерів Playwright заблокований мережевою політикою середовища (403), доступні лише передвстановлені браузери ревізії 1194 → закріплено @playwright/test@1.56.0, що їй відповідає. · Відкат: зняти пін у середовищі з відкритим CDN.
- **Р-14 · Schema-типи вручну.** json-schema-to-typescript із ТЗ §3 не застосовано: схема контракту — артефакт цієї ж сесії (написана під заморожені дані), генерація типів з неї — циркулярна. Типи в `types.ts` синхронізовані зі схемою вручну. · Відкат: додати кодоген-крок у build.

- **Р-15 · Деплой на GitHub Pages.** Обрано GitHub Pages (рішення людини). Workflow `.github/workflows/deploy-catalog.yml` бідить `catalog/` і публікує через вбудований GITHUB_TOKEN, без зовнішніх секретів. Project-site → `BASE_PATH=/altaco-platform-demo`, `SITE_URL=https://alexvshved-star.github.io`; усі внутрішні посилання/ассети проходять через `src/lib/base.ts#withBase`, тож canonical/sitemap/JSON-LD/фіди абсолютні й коректні. Локально `base="/"` — тести й preview без змін. · Відкат: змінити `base`/`site` env у workflow або підключити кастомний домен (CNAME) → `BASE_PATH=/`.
- **Р-16 · Тригер з робочої гілки.** Деплой тимчасово тригериться і з `claude/move-altaco-platform-demo-xlrcml` (не лише `main`), щоб показати живий сайт до мерджу. Після мерджу в `main` рядок гілки з тригера прибрати. · Ризик: якщо середовище `github-pages` має branch-protection на default-гілку — деплой з фіче-гілки заблокується; тоді мерджимо в main (питання до людини).
- **Р-17 · robots.txt / llms.txt на project-site.** На `*.github.io/altaco-platform-demo/` файли `/robots.txt` і `/llms.txt` лежать у підшляху, а краулери шукають їх у корені домену (`*.github.io/robots.txt`), який нам не належить. Для демо прийнятно; для продакшну — кастомний домен, тоді корінь наш. Зафіксовано як «fix later».

- **Р-18 · Мультифото-галерея.** Конвенцію фото змінено на нумеровану: `public/photos/{id}/1.webp,2…` (до 8, суцільна нумерація). Сітка каталогу показує `photos[0]` (фото 1); картка — усі фото: hero = фото 1 + мініатюри з перемиканням (progressive enhancement, без JS усі лишаються в DOM). · Чому: пряма вимога людини «на основній сторінці фото 1, у картці всі три». · Відкат: `resolvePhotos()` + галерея в `[id].astro`.
- **Р-19 · Реальні фото 5 наявних матеріалів.** Користувач надіслав по 3 фото на матеріал у чат; файли на диск не зберігаються, тож відновлено з транскрипту сесії (base64). Зіставлення за кольором/типом: Azul Macauba (блакитний), Arabescato Classico (білий+графіт), Black Tempest (чорний), Brown Silk (сірий струмінь), Mystic Grey (сірий гранітний крап) — усі збігаються з власними фото матеріалів у `codex-learning-lab/feature/stone-gallery`. Порядок = порядок надсилання. Оптимізовано `sharp` → webp (макс. 1400px, q72): 6.0MB → 1.5MB, інакше Lighthouse Perf падав до 76. Скрипт `npm run photos`; сирі jpg видаляються, у репо лише webp. · Відкат: видалити `public/photos/{id}/`.
- **Р-20 · 4 нові матеріали — ОЧІКУЮТЬ рішення людини.** Ще 4 набори фото не відповідають жодному з 5 матеріалів: сірий конгломерат, рівний сірий (soapstone), білий Carrara, Calacatta (біло-золотий). Це НОВІ позиції → додавання в `data/altaco_materials.json` = зміна контракту (CLAUDE.md №1: СТОП, питання людині). Потрібні від людини: назва, type, line (ціну лишаємо 0-плейсхолдером як решта демо). Фото збережено, додам після підтвердження. · Поки в каталог не потрапляють.

- **Р-21 · +5 нових матеріалів (зміна контракту за прямою вказівкою людини).** Користувач надіслав 9 наборів фото з назвами й лініями та команду наповнити каталог. Додано в `data/altaco_materials.json`: `moon-rock` (Bagnara Kitchen), `atlantic-stone` (Bagnara Kitchen), `statuarietto` (Italian Stone), `calacatta-gold` (Italian Stone), `azul-aran` (Bagnara Kitchen). Набір 9 = **Azul Aran** (граніт), а не Mystic Grey — виправлено помилкове розташування фото (фото перенесено `mystic-grey`→`azul-aran`). `azul-macauba`: лінію змінено `bagnara-selection`→`italian-stone` за списком користувача. `mystic-grey` лишено як чернетку (`published:false`, у списку користувача відсутній) — без фото, плейсхолдер. · `type`/`finish` нових позицій — МІЙ здогад за виглядом (moon-rock/atlantic-stone=quartzite, statuarietto/calacatta-gold=marble, azul-aran=granite; фініші polished, atlantic-stone honed), потребує підтвердження людиною. Ціни=0 (плейсхолдер). · Білд: 9 published (+1 чернетка), Lighthouse 92–100, 9 Playwright-тестів зелені.
- **Р-22 · Прайс із Google Sheets унесено.** Egress блокує `docs.google.com` (403), але таблиця прочитана через файловий (Google Drive) MCP сесії. Для 9 матеріалів унесено з прайсу складу: `finish` (Polished/Satinato/Levigato/P.E.C.), `slab_size_mm` (Висота×Ширина), `thicknesses_mm` (20), `price_eur_m2` (роздрібна €/м²: 300–1100). Додано підписи фінішів (satinato/levigato/pec) у `catalog.ts`. Уточнення: де в таблиці кілька записів (Black Tempest 2022/2025, Azul Aran 2024) — узято актуальніший/перший; `type` для KS-позицій у таблиці не вказано (лишив свій здогад). Колір і кислотостійкість у таблиці є, але користувач просив лише обробки/розміри/ціни — не вносив (легко додати за потреби).
- **Р-23 · Ціна в сітці — без «від».** Оскільки в кожного матеріалу одинична роздрібна ціна (без `slab_groups`-діапазону), сітка показує «€X / м²» (як у макеті стор. 8), а не «від €min». «від €min» лишається для майбутніх діапазонів. Тест `expectedGridPrice` оновлено.

- **Р-24 · Сесія супроводу — 3 точкові правки.** (1) Контакти: телефон `+380 97 242 21 21` (tel `+380972422121`), Telegram `t.me/ALTACO_STONE` — у `config.ts` (футер і кнопки беруть звідти). (2) Бейдж наявності з нового поля `stock_location` (kyiv/dnipro/on_order, зашите в даних): kyiv→«В наявності · Київ», dnipro→«В наявності · Дніпро», on_order→«Під замовлення»; той самий компонент/місце; наявність — темний акцентний бейдж, «Під замовлення» — приглушений (`bg-muted`, без нових токенів); JSON-LD availability InStock/PreOrder походить звідси. (3) Орфографія: прибрано подвійну «t» — канон `arabescato-classico` (id, name, slug, тека фото); alt/title/meta генеруються з name — оновились автоматично. Поза цими трьома пунктами нічого не змінено.

- **Р-25 · Hero над каталогом (тільки головна).** Один статичний кадр `hero.jpg` (1600×898, ч/б) → `public/photos/hero/hero-1600.webp` (54KB) + `hero-960.webp` (30KB), q80. Компонент `src/components/Hero.astro`, підключено в `index.astro` над секцією каталогу; нижче hero нічого не змінено. Висота `40vh/45vh/55vh` (lg max 640px), `object-cover`, desktop `object-right`, mobile `object-[70%_center]` (постать у кадрі). Текст ліворуч (overline brass, serif-заголовок як `<p>` — щоб не плодити другий `<h1>` і не чіпати каталог, ivory-палітра), легкий лівий градієнт `from-black/40` для контрасту. CTA «До каталогу ↓» → якір `#catalog` (id додано секції каталогу) + `scroll-behavior:smooth`. LCP-елемент: `loading=eager fetchpriority=high`, явні `width/height` + фіксована vh-висота → CLS=0. Тексти в `i18n/uk.ts#hero`. Джерело 1600px (не 1920) — апскейл не робив. · Лайтхаус цього ходу не зняв: середовище почало глушити будь-який локальний preview-сервер (exit 144); CLS=0 конструктивно, LCP — мінімальний eager-webp, базовий perf до hero був 97–99 (mobile).

- **Р-27 · FORGE-прохід супроводу.** (1) Орфографія: канон проєкту — **«сляб»** (не «слеб»); попередній «слеб»-прохід скасовано (revert у src+data), grep «слеб» = 0. (2) Калькулятор КП: додано поле **«Кількість слябів»** (дефолт 1); поле «Площа сляба, м²» (дефолт = площа сляба з картки). (3) **Канонічна формула** в одному джерелі `format.ts#slabTotal`: `Разом = Площа(2 знаки) × Кількість × Ціна/м²`, **округлення до цілого євро** (раніше були розбіжні round-to-10 на картці й round у модалці). Застосовано однаково в: «ціна за сляб» на картці (`slabPricing`), `price_slab` у `/catalog.json` (`publicFeed`), «Разом» у модалці й PDF. Перевірка: Azul Macauba 6,52×1 = €7 172 скрізь; 6,52×3 = €21 516 у PDF. (4) CTA «Сформувати КП» → **«Сформувати комерційну пропозицію»** (через i18n → всі 9 карток). (5) Фасети: мітки «Лінія / колекція»→**«Виробник / колекція»**, «Фініш»→**«Обробка поверхні»**; перші пункти «—»→текстові плейсхолдери (Усі типи каменю / Усі колекції / Усі види обробки / Усі кольори; сортування — «За замовчуванням»); «—» у dist = 0. (6) Контакти/статус/Telegram — уже актуальні з попередніх сесій (заглушок `hello@altaco.ua`/`+380 44 000 0000`/`t.me/altaco` немає; статус єдиний з `stock_location`); пункти 1–2 ТЗ описували старий деплой.

## Warnings сторонніх інструментів

- npm audit · «astro <=6.1.9: XSS у define:vars; server islands replay» (moderate) · блокер: **НІ** — статичний експорт, `define:vars` не використовується, server islands відсутні. Закрити апгрейдом на Astro 6 окремою сесією.
- Playwright CDN · «403 Host not in allowlist» при `playwright install` · блокер: **НІ** — вирішено піном версії під передвстановлені браузери (Р-13).
- Lighthouse best-practices спершу 96 через 404 на /favicon.ico · виправлено фірмовим favicon.svg → 100.
